# 🚀 **Roadmap ISC² + autres certifications clés pour architecte logiciel DevSecOps / IAM SSO / ISO 27001**

| 🎯 **Niveau**                                     | 📜 **Certification**                                   | 💡 **Pourquoi c’est pertinent pour toi**                           | ⚠️ **Prérequis / Remarques**                                |
| ------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------- |
| 🔰 **Base ISC²**                                  | **SSCP**                                               | Bases solides en sécurité opérationnelle, IAM, contrôles d’accès   | Validation terrain importante                               |
| 🛡️ **Fondation ISO**                             | **ISO 27001 Lead Implementer / Auditor**               | Maîtrise la gouvernance sécurité selon norme ISO 27001             | Complémentaire ISC²                                         |
| ⚙️ **Intermédiaire ISC²**                         | **CISSP**                                              | Couverture complète des 8 domaines sécurité, architecture comprise | Expérience 5 ans, passage obligatoire avant spécialisations |
| 🏛️ **Expertises ISC²**                           | **CISSP-ISSAP** (Architecture)                         | Spécialisation architecture SI sécurisée                           | CISSP obligatoire                                           |
|                                                   | **CCSP** (Cloud Security)                              | Sécurité cloud liée à DevSecOps et IAM/SSO                         |                                                             |
|                                                   | **CSSLP** (Secure Software Lifecycle)                  | Sécurité du cycle de développement logiciel (Security by Design)   |                                                             |
| 🔐 **Compléments IAM/SSO**                        | Certifications IAM dédiées (ex: CIAM, Okta, ForgeRock) | Approfondir IAM et SSO                                             | Hors ISC²                                                   |
| 🕵️ **Sécurité offensive / hacking éthique**      | **CEH (Certified Ethical Hacker)**                     | Comprendre techniques de hacking pour mieux sécuriser              | Fondamentaux sécurité recommandés                           |
| 🔍 **Tests d’intrusion avancés**                  | **OSCP (Offensive Security Certified Professional)**   | Pentesting pratique avancé, exploitation de failles                | Compétences techniques solides nécessaires                  |
| 🧩 **Gestion incidents / Forensics**              | **GCFA (GIAC Certified Forensic Analyst)**             | Analyse d’incidents et investigation forensic                      | Expérience en analyse sécurité recommandée                  |
| 🛠️ **Gestion vulnérabilités / Patch management** | **CompTIA Security+**                                  | Bases solides en sécurité IT, gestion des vulnérabilités           | Très accessible, bon point de départ                        |

# 📅 **Parcours conseillé avec CEH et autres**

### 1️⃣ SSCP → CISSP (socle ISC²)

### 2️⃣ Spécialisations CISSP : ISSAP (Architecture), CCSP (Cloud), CSSLP (DevSecOps)

### 3️⃣ IAM / SSO : Certifications spécialisées (CIAM, Okta...)

### 4️⃣ Sécurité offensive et tests :

* **CEH** pour connaître techniques de hacking, identification des failles
* **OSCP** pour tests d’intrusion pratiques avancés

### 5️⃣ Analyse d’incidents & Forensics :

* **GCFA** pour investigations et gestion incidents

### 6️⃣ Bases complémentaires :

* **Security+** pour renforcer les fondamentaux sécurité IT

## 1. 🔐 **Security and Risk Management**

**Gestion de la sécurité et des risques**

| Sous-domaines clés                                 | Description                                           | Exemples / Cas d’études                      | Outils & Métriques clés                | Bonnes pratiques                                           |
| -------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------- | -------------------------------------- | ---------------------------------------------------------- |
| 🔑 Confidentialité, Intégrité, Disponibilité (CIA) | Modèle de base pour protéger les données et services  | Protection des données personnelles (RGPD)   | Modèles CIA, audits conformité         | Classification claire des données, contrôle d’accès strict |
| 🏛️ Gouvernance de la sécurité                     | Politiques, responsabilités, conformité réglementaire | Mise en œuvre ISO 27001 dans une PME         | Logiciels GRC (RSA Archer, ServiceNow) | Sensibilisation, revue régulière des politiques            |
| ⚖️ Gestion des risques                             | Identifier, analyser, traiter les risques             | Analyse de risques pour migration cloud      | NIST RMF, Risk Register                | Planification et suivi continus des risques                |
| 🔄 Continuité d’activité (BCP/DRP)                 | Préparation et reprise après sinistre                 | Ransomware + plan de reprise après sinistre  | Outils sauvegarde, tests bascule       | Tests réguliers, mise à jour de la documentation           |
| 📜 Compliance & législation                        | Respect des normes et lois (RGPD, HIPAA, SOX…)        | Audit de conformité dans le secteur bancaire | Checklists, audits automatisés         | Veille réglementaire active                                |
| 🤝 Éthique professionnelle                         | Code de conduite, comportement éthique                | Fuite de données due à un abus interne       | Formations, chartes                    | Culture d’intégrité et responsabilité                      |

---

### 📚 Cas pratique 1

Une entreprise déploie un cloud privé. Elle identifie les risques (ex: accès non autorisés, attaques DDoS), applique NIST RMF et établit un plan de continuité avec sauvegardes cryptées.

---

### 📊 Métriques importantes

| 📏 Métrique                     | 📖 Description                            | 🎯 Cible          |
| ------------------------------- | ----------------------------------------- | ----------------- |
| ✅ % risques traités             | Proportion des risques correctement gérés | > 90%             |
| ⏱️ Temps moyen de reprise (RTO) | Durée de restauration après incident      | < 4 heures        |
| 🔄 Fréquence tests BCP          | Nombre de tests annuels                   | Minimum 2 fois/an |

## 2. 🗃️ **Asset Security**

**Sécuriser et gérer les actifs informationnels**

| Sous-domaines clés             | Description                                    | Exemples / Cas concrets                      | Outils & Techniques                         | Bonnes pratiques                                     |
| ------------------------------ | ---------------------------------------------- | -------------------------------------------- | ------------------------------------------- | ---------------------------------------------------- |

## 3. 🏗️ **Security Architecture and Engineering**

**Conception et ingénierie des systèmes sécurisés**

| Sous-domaines clés         | Description                                             | Exemples / Cas d’usage                          | Outils & Méthodes                | Bonnes pratiques                             |
| -------------------------- | ------------------------------------------------------- | ----------------------------------------------- | -------------------------------- | -------------------------------------------- |
| 📐 Modèles de sécurité     | Bell-LaPadula (confidentialité), Biba (intégrité), etc. | Système militaire avec contrôle MAC             | Modélisation UML, Formal Methods | Validation formelle, revue rigoureuse        |
| 🏛️ Architecture sécurisée | Sécurisation hardware, software, réseau                 | Microservices sécurisés avec Zero Trust Network | Sparx EA, ArchiMate              | Défense en profondeur, segmentation stricte  |
| 🔐 Cryptographie           | Chiffrement symétrique/asymétrique, gestion clés        | TLS 1.3 pour échanges HTTPS sécurisés           | OpenSSL, HashiCorp Vault         | Rotation clés régulière, algorithmes récents |
| 🖥️ Sécurité des systèmes  | Protection contre injections, overflow                  | ASLR, DEP sous Windows                          | Fortify, SonarQube               | Revue de code, tests de fuzzing              |
| ☁️ Sécurité Cloud          | Isolation, gestion multi-tenant                         | Isolation comptes AWS, Azure                    | Prisma Cloud, AWS Config         | Monitoring continu, segmentation réseaux     |

---

### 📚 Cas pratique 3

Microservices sécurisés : Zero Trust, segmentation réseau, JWT + OAuth 2.0, pipeline CI/CD avec SAST/DAST.

---

### 📊 Métriques architecture

| 📏 Métrique                   | 📖 Description                        | 🎯 Objectif |
| ----------------------------- | ------------------------------------- | ----------- |
| ✅ % vulnérabilités corrigées  | Failles critiques corrigées           | > 95%       |
| ⏳ Temps moyen de patch (MTTR) | Délai pour correction vulnérabilité   | < 48h       |
| 📈 Couverture tests SAST/DAST | % du code testé par analyses stat/dyn | > 85%       |
